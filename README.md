# Volvo Battery Passport

**Blockchain-Based Supply Chain Transparency**: an educational prototype.

A battery batch is registered on a blockchain and moves through its lifecycle, from mining to recycling. Each step is recorded by an authorised participant who signs the transaction in MetaMask. Anyone can view the batch's public battery passport, including through a QR-code link, without a wallet.

> **Disclaimer.** This project is inspired by automotive battery traceability (Volvo Cars–Circulor). It is **not** an official Volvo Cars or Circulor product and is not connected to their systems. It runs only on a **local Hardhat blockchain**. All demo data is fictional.

---

## Features

- **One Solidity contract** (`contracts/BatteryPassport.sol`) with five roles: Admin, Supplier, Manufacturer, Regulator and Customer.
- **A six-stage lifecycle enforced on-chain:** Registered → Refined → Manufactured → Distributed → End of Life → Recycled. Stages cannot be skipped, repeated or overwritten.
- **Input validation:** unique batch IDs, required text fields, recycled content of 0–100 %, carbon footprint greater than 0.
- **An on-chain audit trail** through the events `RoleGranted`, `RoleRevoked`, `BatteryRegistered` and `StageAdvanced`.
- **A React dashboard** with:
  - MetaMask connection; the role is always read from the contract, never chosen in the UI.
  - Role-based forms; every write is signed in MetaMask and confirmed by its transaction receipt.
  - Public passport lookup that needs no wallet.
  - Full-passport view for Admin and Regulator.
  - A QR code linking to each public passport.
- **24 automated Solidity tests** (forge-std, run by Hardhat).

## Prerequisites

- **Node.js 22 LTS or newer** (tested with Node v24.22.0 and npm 11.19.1)
- **Git**, which npm needs to install `forge-std` from GitHub
- **MetaMask** browser extension (Chrome, Edge, Firefox or Brave)

No paid services, cloud accounts or real cryptocurrency are needed.

## Running the demo

You need three terminals, all opened in the project root.

### Terminal 1: start the local blockchain

```powershell
npx hardhat node
```

Leave this running. It serves `http://127.0.0.1:8545` (chain ID 31337) and prints 20 test accounts with their private keys. The blockchain lives in memory, so **stopping it erases everything**.

### Terminal 2: deploy and seed

```powershell
npx hardhat run scripts/deploy.ts --network localhost
npx hardhat run scripts/seed.ts --network localhost
```

- `deploy.ts` deploys the contract **and writes its ABI + address into `frontend/src/contract.ts`**. The dashboard and `seed.ts` both read the address from that file, so they always target the same deployment.
- `seed.ts` grants the roles below and runs `DEMO-BATCH-0001` through all six stages. Expect `Final stage: Recycled (6)`. It is safe to rerun: it skips roles that are already granted and continues from the batch's current stage.
- `export-frontend.ts` is only needed to refresh the ABI after recompiling (it keeps the current address). To target a specific address, set `$env:BATTERY_PASSPORT_ADDRESS="0x…"` before running it or `seed.ts`.

**After restarting the node**, run both commands again, then in MetaMask open *Settings → Advanced → Clear activity tab data* for each demo account. Otherwise MetaMask reuses nonces from the old chain and reports "Transaction failed".

### Terminal 3: start the dashboard

```powershell
cd frontend
npm run dev
```

Open **http://localhost:5173**. The demo batch passport loads without a wallet.

## MetaMask setup (one time)

### 1. Add the local network

In MetaMask, go to **Settings → Networks → Add a network manually**:

| Field | Value |
|---|---|
| Network name | Hardhat Local |
| RPC URL | `http://127.0.0.1:8545` |
| Chain ID | `31337` |
| Currency symbol | `ETH` |

You can also click **Switch / add Hardhat Local** in the dashboard after connecting.

### 2. Import the test accounts

Go to **Account menu → Add account → Import account**. Paste the private keys of accounts **#0 to #4** printed by `npx hardhat node`. After running `seed.ts`, they hold these roles:

| Account | Address | On-chain role |
|---|---|---|
| #0 | `0xf39F…2266` | Admin (deployer) |
| #1 | `0x7099…79C8` | Supplier |
| #2 | `0x3C44…93BC` | Manufacturer |
| #3 | `0x90F7…b906` | Regulator |
| #4 | `0x15d3…6A65` | Customer |

> ⚠️ These are Hardhat's well-known public test keys. **Never send real funds to them or use them on any real network.**

To act as a different participant, **switch accounts in MetaMask**. The dashboard re-reads the role from the contract automatically.

## Demo walkthrough

1. **Public passport, no wallet**
   - Open http://localhost:5173 without connecting.
   - `DEMO-BATCH-0001` shows the lifecycle tracker at **Recycled**, the public fields and a QR code.
2. **QR link**
   - Open the URL shown under the QR code, e.g. `http://localhost:5173/?passport=DEMO-BATCH-0001`. The passport loads directly.
   - Try an unknown ID such as `NOPE-123`. The dashboard reports that the batch is not registered.
3. **Register a new batch as Supplier (#1)**
   - Click **Connect MetaMask** and select account #1. The role shows **Supplier**.
   - In **1 · Register battery**, enter batch ID `DEMO-BATCH-0002`, a mine location and a material origin. Confirm in MetaMask.
   - The banner shows *Confirmed in block N* and the passport refreshes to **Registered**.
4. **Record refining (#1)**
   - In **2 · Record refining**, enter the details and recycled content (0–100). The stage becomes **Refined**.
5. **Show a rule being enforced**
   - Switch MetaMask to account #2 (**Manufacturer**). Try **4 · Record distribution** for `DEMO-BATCH-0002`.
   - Before MetaMask opens, the dashboard shows the contract's error: *"Stage order violated: prerequisite stage not yet complete"*. Nothing is written.
6. **Record manufacturing (#2)**
   - In **3 · Record manufacturing**, enter the details, a carbon footprint (whole number > 0), a VIN, and tick quality passed. The stage becomes **Manufactured**.
   - Then record distribution.
7. **Regulator view (#3)**
   - Switch to account #3. Click **List all batch IDs**, then **Load full passport**.
   - The full passport also shows the supplier address, registration time and refining details.
8. **Customer (#4)**
   - Switch to account #4. There are no write forms and no full-passport view, only public passports.
   - The contract itself also rejects a full-passport request from this account with *"Access denied: Admin or Regulator role required"* (covered by test 10).
9. **Admin (#0), optional**
   - Grant or revoke a role for any address, then switch to that account and watch the displayed role change.

## Restarting the local node

Stopping `npx hardhat node` wipes all contracts, roles and batches. After starting it again:

1. Rerun the three Terminal 2 commands: deploy, export-frontend, seed.
2. Refresh the dashboard.
3. In MetaMask, for each imported account, go to **Settings → Advanced → Clear activity tab data**. This avoids "nonce too high" errors.

## Troubleshooting

| Symptom | Fix |
|---|---|
| *Cannot reach the local Hardhat node at http://127.0.0.1:8545* | Start `npx hardhat node` in Terminal 1. |
| *No contract responded at 0x…* | The node was restarted. Deploy again, then run `export-frontend.ts` and `seed.ts`. |
| *No contract at 0x…* when running `seed.ts` | Same as above; set `BATTERY_PASSPORT_ADDRESS` if the address changed. |
| Network shows a chain ID other than 31337 | Click **Switch / add Hardhat Local**, or select Hardhat Local in MetaMask. Writes stay disabled until you do. |
| "Nonce too high" or a transaction stuck in MetaMask | MetaMask → Settings → Advanced → **Clear activity tab data**. |
| Role shows **None** | That account has no role. Run `seed.ts`, or grant one as Admin (#0). |
| *MetaMask was not detected* | Install or enable the extension. Public passports still work without it. |
| `npm install` fails on `forge-std` | Install Git and make sure `git` is on your PATH. |

## Limitations

- **Local only.** Nothing is deployed to a public blockchain, and state resets when the node restarts.
- **Records, not proof of truth.** The blockchain shows who submitted a value and that it has not changed since. It cannot verify that origin, recycled content or carbon footprint are accurate.
- **Access control is not confidentiality.** Role checks restrict who may call functions; they do not encrypt anything. All on-chain data is readable by anyone with node access.
  - The Admin/Regulator check on `getFullPassport` is a view-function check, and a read call's `from` address can be set freely, so it is not a privacy control.
  - Write functions are protected properly, because `msg.sender` is proven by the transaction signature.
- **Same-computer QR codes.** QR links point to `localhost` and only work on the machine running the app and node.
- **No corrections.** Once a stage is recorded it cannot be changed.
- **Single Admin key.** If its key is lost, or the Admin revokes its own role, role management stops working.

Possible future work (not implemented): a permissioned network, confidential data off-chain with hashes on-chain, supplier audits and certificates, multi-signature admin, and battery health and repair history.
